# CORA Project — Development Standards

## Project Overview
CORA (Cognitive Operator Reactor Assistant) is a student-facing learning tool built on Neo4j knowledge graphs. It has a public landing page, an authenticated student frontend, and an admin app.

## Student UI work — read this first
Before changing anything under `frontend/src/components/Student/`, read
[docs/STUDENT_UI.md](docs/STUDENT_UI.md). It holds the agreed design direction
(concept-first navigation), the screen inventory with build status, the semantic
mastery colours, and the guest-access model.

The five artboards it refers to are in [docs/artboards/](docs/artboards/README.md):
`png/` to look at, `view/*.html` to open in a browser, `source/*.dc.html` for exact
hex and pixel values, and `README.md` for a per-screen build spec. Read the README's
token appendix before porting any artboard to Tailwind — half its palette (stone,
amber, teal) is not generated by `frontend/tailwind.config.js` and fails silently.

## Tech Stack
- **Frontend**: React 18, TypeScript, Tailwind CSS v4, React Router 6
- **UI Libraries**: Neo4j NDL (`@neo4j-ndl`), Neo4j NVL (`@neo4j-nvl`), Material UI, react-icons
- **Auth**: Auth0 with JWT, role-based (admin, ta, student)
- **Backend**: Python/FastAPI, Neo4j, PostgreSQL

## Tailwind Configuration
- Tailwind **v4** via `@import 'tailwindcss'` in `src/index.css`, with the v3-style
  `tailwind.config.js` pulled in by `@config`.
- **`corePlugins: { preflight: false }` does NOT work.** Tailwind v4 dropped `corePlugins`,
  so that line is silently ignored and v4's preflight is active.
- **`@neo4j-ndl/base` is imported into a cascade layer, and must stay that way.**
  `src/index.css` declares `@layer ndl, theme, base, components, utilities;` and then
  imports the NDL stylesheet with `layer(ndl)`. Do **not** move that import back into a
  component (it used to live in `Home.tsx`) and do not drop the `layer(...)`.
  - Why: NDL ships its own compiled Tailwind preflight as plain, **unlayered** CSS.
    Unlayered CSS outranks every `@layer` regardless of specificity, so while the import
    was unlayered, NDL's `*{border-width:0}` and `button{…}` resets silently killed
    `border`, `shadow-*`, `p-*`, `bg-*` and text colors **app-wide** — every card across
    the landing page and student frontend rendered borderless and flat, with no error and
    the classes present in the DOM.
  - With the layer in place, normal Tailwind utilities work everywhere, buttons included.
    Prefer plain classes; reach for inline styles only where you have measured a conflict.
- **Shadow utilities are defined in `index.css` under `@theme`, not in the config.**
  The NDL preset sets v3-style `theme.boxShadow`, which *replaces* Tailwind's scale with
  six NDL names — so `shadow-sm` / `shadow-lg` generated no CSS at all. Tailwind v4 reads
  shadows from `--shadow-*` theme variables, which `index.css` now declares.
- Still add `box-border` or `style={{ boxSizing: 'border-box' }}` on layout roots.
- **Only the colors listed in `tailwind.config.js` are generated** (`red`, `slate`, `white`,
  `black`, `gray`, `emerald`, `stone`, `amber`, `teal`). Any other palette — `blue`,
  `indigo`, … — produces no CSS at all and fails silently. Add it to the config before
  using it. (`stone`/`amber`/`teal` were added for the artboard palette; see
  `docs/artboards/README.md`.)
- **`-20` spacing utilities are 20px, not 80px.** The NDL preset extends `theme.spacing`
  with a px-valued scale that matches Tailwind's at every key *except* `20`, which it sets
  to `20px` — Tailwind's default is `5rem` (80px). So `h-20`, `w-20`, `p-20`, `py-20`,
  `pb-20`, `gap-20` and `mt-20` all render at a quarter of the intended size, silently,
  with the class present in the DOM. The keys either side (`16` = 64px, `24` = 96px) are
  correct, which makes it read as a layout mistake rather than a config one. This shipped
  a 20px-tall mobile tab bar with every label clipped off-screen. Use an arbitrary value
  (`h-[74px]`) when you mean roughly 80px. **`py-20` on the landing page is still
  affected** — its sections are padded 20px where the design calls for 80px.
- **Debugging rule:** if a Tailwind class appears to do nothing, do not re-read the JSX.
  Measure it — `getComputedStyle` on a probe element in the running app will tell you in
  seconds whether the rule is missing entirely or being overridden.

## Design Tokens — Landing Page & Student Frontend

### Colors
- **Primary**: `red-600` (#dc2626) — buttons, CTAs, logo, accents
- **Primary hover**: `red-700` (#b91c1c)
- **Surface tinted**: `red-50` (#fef2f2) — section backgrounds, card tints
- **Border**: `red-100` (#fee2e2) — card borders, dividers
- **Border hover**: `red-200` (#fecaca)
- **Text primary**: `slate-900` (#0f172a)
- **Text secondary**: `slate-500` (#64748b)
- **Text muted**: `slate-400` (#94a3b8)
- **Background light**: `white` — alternates with `red-50` between sections

### Typography
- Hero headings: `text-5xl md:text-6xl font-bold tracking-tight leading-[1.08]`
- Section headings: `text-2xl font-bold tracking-tight`
- Eyebrow labels: `text-xs font-semibold uppercase tracking-wider text-red-500`
- Body: `text-sm leading-relaxed text-slate-500`
- Small labels: `text-[11px] font-semibold uppercase tracking-wider`

### Spacing
- Section vertical padding: `py-16` to `py-24`
- Container horizontal padding: `px-6`
- Max content width: `max-w-5xl` (consistent across all sections)
- Card padding: `p-6`
- Grid gap: `gap-6` to `gap-8`

### Components
- **Buttons (primary)**: `rounded-full bg-red-600 px-8 py-3 text-sm font-semibold text-white shadow-lg shadow-red-300 hover:bg-red-700`
- **Buttons (secondary)**: `rounded-full border border-red-200 bg-white px-6 py-3 text-sm font-medium text-red-600 hover:border-red-300`
- **Cards**: `rounded-2xl border border-red-100 bg-white p-6 shadow-sm hover:border-red-200 hover:shadow-md`
- **Icon containers**: `h-10 w-10 rounded-xl bg-red-50 text-red-600`
- **Pill badges**: `rounded-full border border-red-200 bg-white px-3 py-1 text-[11px] font-semibold uppercase tracking-wider text-red-600`

### Layout Pattern
- Sections alternate backgrounds: `bg-red-50` → `bg-white` → `bg-red-50` → `bg-white`
- No gradient dividers between sections — the alternating colors provide separation
- Blurred decorative orbs: `absolute rounded-full bg-red-100 blur-3xl` on tinted sections

## Local dev gotchas

- **Editing `frontend/.env` needs `--force-recreate`, not `restart`.** Compose injects
  `env_file` values into the container's process environment at *creation* time, and Vite
  prefers `process.env` over the `.env` file it reads from the volume mount. So after
  editing `frontend/.env`:
  `docker compose -f docker-compose.dev.yml up -d --no-deps --force-recreate frontend`.
  A plain `docker restart frontend-dev` leaves the old values compiled into the bundle and
  is very confusing to debug.
- **Put comments on their own line in `.env` files**, not trailing after a value.
- **The `/app` route is broken in the Docker dev setup.** The container's WORKDIR is `/app`
  (from `volumes: ./frontend:/app`), so the URL path `/app` collides with a real directory
  and Vite tries to resolve it as a package: *"Failed to resolve entry for package /app"*.
  `/` and `/student` are unaffected. Fix properly by changing the WORKDIR (e.g. `/srv/app`)
  in `frontend/Dockerfile.dev` and `docker-compose.dev.yml`. Ingestion does not depend on
  it — use `backend/ingest_pdfs.py`.
- **Chat's answer text renders via a `requestAnimationFrame` typing animation.** rAF does
  not fire in a hidden/background tab, so in headless or backgrounded browser testing the
  response bubble looks empty even though the API returned a correct answer. Verify Chat
  from the network response, not the rendered text.

## Backend gotchas

- **`Neo4jGraph(sanitize=True)` deletes any list in a result that holds more than 128
  items.** The option exists to strip embedding vectors, but it applies to every list in
  every row. The course-map query returns its nodes and its relationships as two lists, so
  once the course had more than 128 relationships the entire list vanished — HTTP 200, no
  error, and the Graph tab rendered 120 unconnected dots; asking for more than 128 concepts
  emptied the map completely. `backend/src/learning/graph.py` now passes `sanitize=False`,
  because every query there returns explicit scalar projections and never a raw node.
  Covered by `backend/tests/test_learning_network_live.py`.
- **`ORDER BY` and `LIMIT` are sub-clauses of the `WITH` above them, and must come before
  that `WITH`'s `WHERE`.** Writing `WITH … / WHERE … / ORDER BY … / LIMIT …` is a syntax
  error, not a style choice. To filter first and then order, add a second `WITH` to order
  and truncate on. `backend/tests/test_learning_cypher_syntax.py` runs `EXPLAIN` over every
  `*_QUERY` constant against the live database and catches this class of error.
- **A unit test that hands a fake graph to a query function never parses the Cypher.** The
  fake's `query()` ignores the string entirely, so an invalid query keeps the suite green —
  which is exactly how a broken course map shipped with 42 passing tests. Any new Cypher
  needs a live-database check alongside its fake-graph one.
- **Run the backend suite from the container**, where the dependencies and Neo4j settings
  live: `docker exec backend-dev sh -c "cd /code && python -m unittest discover -s tests -p 'test_*.py' -t ."`

## File Structure
- `frontend/src/components/Landing/` — Public landing page
- `frontend/src/components/Student/` — Authenticated student frontend (Chat, Explore, Learn tabs)
- `frontend/src/components/Auth/Auth.tsx` — Auth0 guard with role-based routing
- `frontend/src/App.tsx` — Route definitions

## Routing
- `/` — Public landing page (when auth enabled)
- `/app` — Admin/TA app (AuthenticationGuard redirects students to /student)
- `/student` — Student frontend (StudentGuard)
- `/callback` — Auth0 callback
- `/chat-only` — Standalone chat

## Key Patterns
- Student frontend uses **state-based tabs** (not routes) so chat state persists across tab switches
- `envConnectionAPI()` for auto-connecting to Neo4j without a modal
- `useOutletContext` is NOT used in the student frontend — each tab is a standalone component
- Always use `react-icons/hi2` for Heroicons in the landing/student pages
